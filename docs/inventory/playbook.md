# ReviOS playbook tweak inventory
1. Bullet counts: Privacy & Telemetry 31 | Appx Bloat Removal 10 | Windows Features & Capabilities 11 | Services 20 | Scheduled Tasks 13 | Performance 28 | Gaming 8
2. Power 11 | Security 16 | Windows Update 14 | Explorer & Shell 20 | Start Menu & Taskbar 8 | Appearance 9 | Context Menu 4
3. Network & DNS 11 | AI (Copilot/Recall) 8 | Edge/OneDrive/Teams 10 | Misc 13 | Ordering notes 12 bullets (~225 tweak bullets; many group several registry values)
4. User options in playbook.conf: 16 (browser, Defender on/off, hibernate on/off, 4 components, 4 appx, 4 general, 2 general-2); everything else is always applied.
5. Caveat: much heavy lifting (Defender, VBS, powerplan, NTFS, service grouping, WU pause) is done by external `revitool.exe`, internals not in this repo. The WinSxS/appx **component-removal** internals ARE now available — `references\packages` — and are decoded in the "CBS removal packages" section below.

Source: ReviOS playbook (AME Wizard), `references\playbook\src`. Notation: HKCU entries are almost always ALSO written to `HKU\.DEFAULT` (default-user template) with the same data; "(+DEFAULT)" below means that mirroring. "revitool X" = external Revision Tool (`%ProgramFiles%\Revision Tool\revitool.exe`, installed in start.yml, NOT in this repo) - its exact registry/service effects are opaque here and would have to be reimplemented. Unless `opt:` names a playbook option, the item is ALWAYS applied.

## CBS removal packages (`references\packages` — resolves the "opaque revitool winpackage" items above)

Source: `meetrevision/packages` (the repo whose release `.cab`s `revitool winpackage --install <name>` and revision-tool's `DefenderRemovalService` download and install). Each package is a declarative YAML (`schema.json`) compiled to a signed CBS cab. These are the internals the inventory above marks "(opaque)".

**Shared mechanism (component supersession).** For every `target_component`, the package emits a component *update* at version `38655.38527.65535.65535` (effectively max), so CBS treats it as the newest revision and it supersedes Microsoft's real component in the WinSxS store. With no `files`/`registry_keys` payload the component is superseded by an empty one — its files/registration drop out while the servicing manifest stays consistent (cleaner and more update-durable than deleting files; this is why it survives where the deprecated raw-`systemPackage` delete caused issue #49). Three payload escape hatches in the schema:
- `stub` — replace a DLL with an **export-only PE stub** (same export names, no-op bodies) so static importers still link. Used where outright removal would break boot/dependents.
- `registry_keys` — set values (per-component, `perUserVirtualization` flag mirrors to user hives).
- `files` — `operation: replace` with `source` (swap a file) or empty `text` (delete).

Install path: `Add-WindowsPackage -Online -NoRestart -IgnoreCheck -PackagePath <cab>`. Cabs are signed with a **MeetRevision** cert carrying the Windows System Component Verification EKU `1.3.6.1.4.1.311.10.3.6`, which must be trusted on the target (ReviOS images pre-trust it) or DISM rejects the package. `amd64` and `arm64` YAMLs are mirrors; details below are from the `amd64` files. Commented-out entries are documented because they encode *what ReviOS deliberately keeps and why*.

## Ordering & dependency notes

Execution order (main.yml): os-info/edition -> os-info/oem-info -> start.yml -> packages/app-win32 -> packages/win-sxs -> packages/appx -> kill explorer & shell hosts -> software.yml -> services.yml -> registry.yml (explorer, privacy, security, system, updates, misc; os-info again) -> revert.yml -> final.yml.

- **Revision Tool first**: start.yml installs `revitool.exe` (and VC++ redist) before anything; app-win32, win-sxs, appx, vbs, powerplan, hibernate, TSX, NTFS, service-grouping, defender, patches ALL depend on it. A custom tool must reimplement each revitool verb used: `appx --all-users --remove`, `winpackage --install {system-components-removal,ai-removal,onedrive-removal,xbox-removal,telemetry-removal}`, `tweaks security {defender,vbs}`, `tweaks performance {powerplan,superfetch,background-apps,ntfs-last-access,ntfs-8dot3-naming,intel-tsx,service-grouping}`, `tweaks utilities {hibernation,fast-startup}`, `tweaks updates {wu-pause-updates,wu-drivers}`, `tweaks personalization input-personalization`, `registry hide-page`, `msstore-apps`, `tweaks patches`.
- **"Uninstalling WinSxS packages before app-win32 could leave leftovers"** (comment in main.yml) - yet actual order runs app-win32 THEN win-sxs; i.e. remove Win32 (Edge/OneDrive/Teams) first, WinSxS second.
- **Defender needs Explorer running** to disable some protections; hence explorer + SearchApp, SearchHost, RuntimeBroker, TextInputHost, ShellExperienceHost, backgroundTaskHost, Widgets are `taskKill`ed only AFTER win-sxs.yml (defender step) and before software/services/registry. Explorer restarted at very end of final.yml.
- **win-sxs.yml comment**: "!systemPackage: method of removing system packages is now deprecated and not recommended, one of the main causes of #49" (replaced by revitool winpackage).
- **AME requirements**: Defender Tamper Protection off ("DefenderToggled"), no 3rd-party AV, no pending updates, plugged in, internet connected.
- **revert.yml runs after registry.yml and final.yml-dependent items**: it deletes whole key `HKLM\Software\Policies\Microsoft\Windows\WindowsUpdate` (so `UpdateNotificationLevel=2` written by notifications.yml is wiped; updates now rely on `wu-pause-updates` via revitool) and `HKLM\...\Defender\Signature Updates` (then re-adds DisableScheduledSignatureUpdateOnBattery=1). Also runs `revitool tweaks performance superfetch enable` and `background-apps enable`, undoing earlier disables - ordering/duplicate intent matters. `onUpgrade: true` means it runs on upgrades from older playbook versions only (verify; applied in sequence anyway).
- **Gotchas recorded in comments**: disabling edgeupdate breaks WebView2 install from Visual Studio (kept Manual); `DisableWindowsConsumerFeatures` breaks Your Phone (not set); `bam` disabled breaks Efficiency Mode (reverted); `SvcHostSplitThresholdInKB` breaks XboxGipSvc (reverted, replaced by revitool service-grouping); `HeapDeCommitFreeBlockThreshold` reverted; disabling Superfetch core breaks `defrag c: -b`; background-apps disabled breaks Game Bar KGL update; `MouseHoverTime` lowered caused overlapping tooltips; `VulnerableDriverBlocklistEnable=0` breaks THE FINALS; `AppCaptureEnabled` set breaks Game Bar Start Recording (#74); bbr2 breaks websockets (#27); `disabledynamictick yes` breaks ROG Ally sleep (#167); Block-Windows-Insider firewall rule breaks Xbox; `NoAutoUpdate=1` once broke Xbox sign-in on old W10; ComputerName rename "causes Network Sharing issues"; `condrv` must be Automatic (0xd000003a, #184); DisableAutomaticRestartSignOn caused slow Hello logon; Contacts consent Deny needed by Mail&Calendar (so left); Hibernate disable may overheat laptops in sleep; DisableRootAutoUpdate needed for MS Store; Edge removal needs non-EU region for the BrowserReplacement trick; Edge/WebView/Dev removal "still gets reinstalled after Windows Updates" hence Deprovisioned keys + EdgeUpdate policies; `since 22621.1343 Windows 11 tries to reinstall WebExperience even if removed` hence Dsh\AllowNewsAndInterests=0; #61 WsxPackManager.dll rename approach reverted (restores `.bak` files in MicrosoftWindows.Client.CBS); Photos removal needs classic Photo Viewer + file assoc re-mapping; Outlook for Windows may auto-install when legacy Mail removed (W10) so removed again at first logon.

Many tasks run `runas: currentUserElevated` vs TrustedInstaller (Explorer GroupBy edit needs TI; Bags cleanup needs current user).
