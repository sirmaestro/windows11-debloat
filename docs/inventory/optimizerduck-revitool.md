## optimizerDuck revert design

Goal: every apply records enough information to put the machine back, per optimization, with no shared global backup.

- **Change set as the unit.** Each optimization's `ApplyAsync` runs against an `OptimizationContext` that exposes `context.Changes` (a `ChangeSet`). Every primitive (RegistryService.Write/DeleteValue/DeleteSubKeyTree/CreateSubKey, ServiceProcessService.ChangeServiceStartupTypeAsync, ScheduledTaskService.DisableTask, hibernation, USB power, power plan install, shell command) reads the PREVIOUS state first and appends a `Change` entry: name, description, ok flag, optional `Revert` step (compensation), optional error/ErrorDetail, optional `Retry` delegate. Skips (already in desired state) and not-applicable results are recorded too, so a "nothing to do" is distinguishable from a failure.
- **Typed revert steps (`Domain\Revert\Steps`)** implementing `IRevertStep { Type, Description, ToData(), ExecuteAsync(RevertContext) }`:
  - `RegistryRevertStep` (action enum RestorePrevious / NoPreviousValue(delete) / DeleteKey / RestoreKey / RestoreKeyTree; Path, Name, previous Value + RegistryValueKind, CreatedSubKeys deepest-first, nested SubSteps).
  - `ServiceRevertStep` (ServiceName, OriginalStartupType), `ScheduledTaskRevertStep` (FullPath, OriginalEnabled), `ShellRevertStep` (ShellType, Command to undo), `PowerPlanRevertStep` (PreviousSchemeId, InstalledSchemeId), `PowerSettingRevertStep` (scheme/subgroup/setting GUIDs, previous AC and DC values), `HibernationRevertStep` (WasPresent: bool? where null = unknown -> revert leaves system alone), `UsbPowerRevertStep` (list of per-device instance name + prior enable flag).
  - Steps are registered in a type-name -> factory dictionary (`RevertManager._stepRegistry`, built by reflection) for deserialization from the stored `Type` string.
- **Persistence (`Services\Revert\RevertManager`, `Domain\Revert\RevertData`).** One JSON file per optimization GUID under `%LOCALAPPDATA%\optimizerDuck\Revert\<guid>.json`: `{ SchemaVersion:1, OptimizationId, OptimizationName, AppliedAt, Steps: [ {Index, Type, Data(JObject)} | null ... ] }`. Steps array is 1-based indexed with null gaps. Writes are atomic (write temp file, then replace/move) and guarded by a per-item `SemaphoreSlim` file lock (30 s timeout). Cancellation is not honored mid-write. Re-applying APPENDS new steps (never dedupes/overwrites) so the oldest backup still restores the true original state.
- **Revert execution.** Load steps, sort by Index DESCENDING (LIFO), run each `ExecuteAsync`; failures are collected as `Change` objects with a Retry delegate and do not abort the loop. Outcome rules: all succeeded -> delete revert file; partial -> rewrite file with only the failed steps (single load-modify-write; `CleanupFailed` flag if that write fails, leftover retried next time); all failed -> keep file, `AllStepsFailed`. `RevertResult { Success, Message, FailedSteps, AllStepsFailed, CleanupFailed }`. Missing/unreadable file -> distinct error messages ("no data" vs "unreadable, parked file found").
- **Retry.** A failed apply step stores a retry closure; if the retry later succeeds `AppendRevertStepAsync` adds its compensation as a NEW entry (LIFO keeps correctness).
- **Compensation saved even on partial failure** (a step refused after changing something still records its previous state).
- **History (`Services\History\ChangeRecordStore`).** Separate from revert data: `%LOCALAPPDATA%\optimizerDuck\History\<guid>.json` stores a `ChangeRecord` (what the last apply did, per step status). Written atomically (`.tmp` then `File.Replace`), best-effort (logged, never fails the apply); survives revert (revert deletes its own file, history stays); unreadable record reads as null, not as an empty run.
- **Safety net.** `SystemRestoreService` can create a restore point (WMI SystemRestore, temporarily lowers the 24h frequency throttle).
- **Idea to copy for our CLI:** snapshot-before-write inside each primitive, one JSON per tweak id, LIFO revert with partial-failure pruning, atomic file replace, separate append-only-ish history, unknown-state => do nothing on revert.
- Customize toggles (Desktop/Gaming/Preferences/SystemFeatures) are `RegistryToggle` objects with OnValues/OffValues/DefaultValue (+IsOptional, null = value absent), state read live from registry, with a RefreshScope post-action (e.g. broadcast desktop icons refresh, policy update, restart explorer) and a registry watcher for external changes; they go through the same OpCall/revert plumbing.

## revitool CLI commands

Binary `revitool` (Dart `args` CommandRunner; no args launches `revitoolw.exe` GUI). Exit codes: 55 = unsupported (non-ReviOS) / appx bridge unavailable, 64 usage, 66 no match, 69 removal refused, 71 enumeration failed, 1 other. Toggle groups are code-generated from `@CliToggle/@CliEnumSubCommand/@CliValue` annotations: `revitool tweaks <category> <name> enable|disable|status`; enum groups use `status|set <value>` or `enable|disable <enum>`.

Top-level: `appx`, `msstore-apps`, `registry`, `tweaks`, `winpackage`.

- `revitool appx --list [--provisioned] [--match <prefix,...>] [-e <pattern>]` / `--users <name,...>` / `--remove <name,...> [--all-users | --preserve-roaming] [--no-schedule-startup] [-e ...]`
- `revitool msstore-apps --id <ProductId,...> [-r Retail|<ring>] [-a auto|<arch>] [--download <path>]` (omit --download to install)
- `revitool registry hide-page --value <page>` / `unhide-page --value <page>`
- `revitool winpackage --download|--install|--uninstall <system-components-removal|telemetry-removal|defender-removal|ai-removal|onedrive-removal|xbox-removal> [--download-path <dir>] [--force]`
- `revitool tweaks patches` (stub: applies main playbook patch, currently only logs)
- `revitool tweaks performance`: toggles `powerplan`, `powerplan-states-c6`, `superfetch`, `memory-compression`, `intel-tsx`, `swapchain-fso`, `swapchain-wo`, `swapchain-mpo`, `background-apps`, `ctfmon-input`, `ntfs-last-access`, `ntfs-8dot3-naming`, `ntfs-memory-usage`; enum `service-grouping` (forced|recommended|disabled) status/set; value `background-window-message-rate-limit` (3..20 ms duration) status/set
- `revitool tweaks personalization`: enum `notification` (on|offMinimal|offFull); toggles `legacy-balloon`, `screen-edge-swipe`, `new-context-menu`, `input-personalization`, `caps-lock`, `explorer-home`, `explorer-gallery`
- `revitool tweaks security`: toggles `defender` (force variants exist), `uac`, `vbs`, `memory-integrity`; enum `mitigation` (meltdownSpectre|downfall) enable/disable/status
- `revitool tweaks updates`: action `certificates`, action `kgl`, toggles `wu-pause-updates`, `wu-visibility`, `wu-drivers`
- `revitool tweaks utilities`: toggles `hibernation`, `fast-startup`, `modern-standby`, `tm-monitoring`, `usage-reporting`

Helper mechanisms worth reusing: TrustedInstaller execution token for protected keys/services (core\trusted_installer), `HKLM\SYSTEM\ControlSet001\Services\<name>\Start` writes for service start-type (4=Disabled, 3=Manual, 2=Auto, 0/1=boot/system), `getUserServices(prefix)` to enumerate per-user service instances (`<name>_<luid>`), and explorer restart via `taskkill /im explorer.exe /f` then `explorer.exe`.
