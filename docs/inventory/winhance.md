Notation used in mech: `HIVE\key\Value [Type rec=<Winhance recommended> on=<value when toggle ON/feature enabled> off=<value when OFF> def=<Windows default>]`. "null"/"-" means the value is deleted/absent. `on`/`off` refer to Winhance's toggle semantics (ON = Windows feature enabled), so the debloat value is normally `rec`. `options:` lists combo-box choices as `Label(*REC=Winhance recommended)(def=default):ValueName=data`. `[pref]` = Winhance marks it a subjective preference (not auto-applied in its "recommended" set). Service start types are written as registry HKLM\SYSTEM\CurrentControlSet\Services\<svc>\Start (2=Auto, 3=Manual, 4=Disabled); Winhance changes services purely via the Start registry value (plus restart), not sc.exe. Policy entries flagged by IsGroupPolicy in source write the HKLM/HKCU ...\Policies\... keys (Winhance has a PolicyCleanupService that deletes them when the user reverts to default). Scheduled tasks are toggled through the Task Scheduler COM API (task.Enabled). Descriptions are Winhance's own wording shortened; some names/labels are localisation keys (e.g. ServiceOption_Disabled=Start 4, ServiceOption_ManualRecommended=Start 3).
Risk labels are my assessment, not from Winhance.

## Autounattend generator (AdvancedTools)

What it exposes: it has no private option list; it exports the *current Winhance selections* (every Optimize/Customize setting state the user has configured, including combo selections and power plan, plus the ticked Windows Apps/capabilities/features) into a config and renders `autounattend.xml` from an embedded template (Winhance.UI/Features/Common/Resources/AdvancedTools/autounattend-template.xml). There is also a WIM util wizard (Step1 pick ISO/WIM, Step2 add XML, Step3 add drivers (DriverCategorizer), Step4 build ISO with oscdimg). Fixed (non-optional) behaviour of the template:
- windowsPE pass (x86/arm64/amd64): HKLM\SYSTEM\Setup\LabConfig BypassTPMCheck / BypassSecureBootCheck / BypassStorageCheck / BypassCPUCheck / BypassRAMCheck / BypassDiskCheck = 1; placeholder product key 00000-00000-00000-00000-00000 with WillShowUI=Always; AcceptEula=true.
- specialize pass (RunSynchronous, in order): (1) extract the embedded script from `<Extensions><File path=...>` of C:\Windows\Panther\unattend.xml to disk via a custom ExtractScript scriptblock; (2) HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\OOBE\BypassNRO=1 (local account); (3) `Get-NetAdapter | Disable-NetAdapter` (offline during OOBE so no updates/MSA forced); (4) enable .NET Framework 3.5 from install media (loops drive letters C..K for sources\sxs\*.cab, dism /Online /Enable-Feature NetFx3); (5) run C:\ProgramData\Winhance\Unattend\Scripts\Winhancements.ps1 as SYSTEM (system-wide pass).
- oobeSystem pass: HideEULAPage, HideOEMRegistrationScreen, HideOnlineAccountScreens, HideWirelessSetupInOOBE = true, NetworkLocation=Work, ProtectYourPC=3; FirstLogonCommand re-enables all network adapters.
- Generated Winhancements.ps1 (validated for PS syntax and XML well-formedness before writing UTF-8 without BOM) has two modes selected by the `-UserCustomizations` switch: (a) system-wide pass: embeds and runs BloatRemoval.ps1 / EdgeRemoval.ps1 / OneDriveRemoval.ps1 from C:\ProgramData\Winhance\Scripts and registers their tasks; applies power settings; emits HKLM registry entries for all Optimize and Customize settings; applies a clean Start menu (always: Win11 = HKLM\SOFTWARE\Microsoft\PolicyManager\current\device\Start\ConfigureStartPins={"pinnedList":[]}; Win10 = empty LayoutModification.xml in Default user Shell folder); registers task \Winhance\WinhanceUserCustomizations; creates a desktop shortcut "Install Winhance" in the Default user's Desktop (irm get.winhance.net | iex); includes empty "ADD YOUR SYSTEM WIDE POWERSHELL SCRIPT" placeholder; (b) user pass: HKCU entries applied once per user, guarded by marker HKCU\Software\Winhance\UserCustomizationsApplied=1 (delete to re-apply). When started as SYSTEM it waits up to 12x10 s for a logged-in user, resolves SID, launches itself as the interactive user (CreateProcessAsUser helper) and reboots (`shutdown /r /t 20`) after success; HKU-based marker check. Settings that rely only on NativePowerApi have no unattend emitter (warned in log). Includes a user-specific placeholder block.

## Re-apply / persistence mechanism

Settings (registry/service/task tweaks) are NOT re-applied by any background job; they are written once by the Winhance app (and by Winhancements.ps1 for unattend installs). Persistence exists only for the *removal scripts*, which Winhance re-runs because Windows Update / provisioning can bring Edge, OneDrive and Appx apps back:
- Scripts are generated into C:\ProgramData\Winhance\Scripts\: BloatRemoval.ps1 (v2.3, merged/accumulated across runs: new package/capability/feature names are merged into the existing script's `$packages/$capabilities/$optionalFeatures/$specialApps` arrays; removing an item from the UI strips it from the arrays and the task is deleted when arrays are empty), EdgeRemoval.ps1 (v1.4), OneDriveRemoval.ps1. Logs go to C:\ProgramData\Winhance\Logs\*Log.txt (rotated at 500 KB). Scripts self-elevate and run fine as SYSTEM/in a task.
- Each script is registered (Task Scheduler COM, or New-ScheduledTask* in the unattend path) in task folder `\Winhance\` as SYSTEM, LogonType service account, RunLevel Highest, ExecutionTimeLimit 0 (unlimited), runs on battery: BloatRemoval = trigger AtLogon; OneDriveRemoval = AtLogon; EdgeRemoval = AtStartup; OpenWebSearchRepair (Edge protocol handler repair) = AtLogon; WinhanceUserCustomizations = AtLogon. Action = `powershell.exe -ExecutionPolicy Bypass -NoProfile -Command "iex([IO.File]::ReadAllText('<script>'))"` (COM path; the iex-of-file form is used so the task works even if the machine execution policy blocks -File) or `-File` in the unattend path. Existing task is deleted and re-registered (2 s wait for task-cache reset).
- If the machine ExecutionPolicy blocks running the script immediately (ExecutionPolicyException), removal is "DeferredToScheduledTask" (the task runs it at next logon/startup).
- Self-update: RemovalScriptUpdateService.CheckAndUpdateScriptsAsync compares the "Script Version: x.y" header inside the on-disk scripts to the app's constants (Edge 1.4, OneDrive 1.2, BloatRemoval 2.3) and rewrites/re-registers when outdated (Edge/OneDrive re-run after update; BloatRemoval is regenerated from its existing arrays and not re-run).
- Because the tasks run each logon/startup, the BloatRemoval script is idempotent (queries Get-AppxPackage -AllUsers / Get-AppxProvisionedPackage once, only acts on matches; capabilities matched by `Name -like "<cap>*"` and State=Installed; optional features only if Enabled) and the Edge script exits early if no Edge is detected (but still re-installs/repairs the protocol redirect and deletes any *Edge* scheduled tasks except its own).
- Xbox side effect handled in BloatRemoval: when Microsoft.GamingApp / XboxGamingOverlay / XboxGameOverlay are removed it writes HKCR\ms-gamebar and HKCR\ms-gamebarservices protocol keys (URL Protocol, NoOpenWith, shell\open\command = %SystemRoot%\System32\systray.exe) to suppress the "get an app for ms-gamebar" Store popup, and sets HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\GameDVR\AppCaptureEnabled=0, HKCU\System\GameConfigStore\GameDVR_Enabled=0, HKLM\SOFTWARE\Policies\Microsoft\Windows\GameDVR\AllowGameDVR=0 (for the interactive user's HKU\<SID> when running as SYSTEM).
- Policy cleanup: when the user switches a setting back to default, PolicyCleanupService deletes the Policies keys Winhance created (no persistence needed).

## Edge/Defender/OneDrive removal approach

Edge (EdgeRemoval.ps1, v1.4; credits: ishad0w for legacy Edge, FR33THY Ultimate-Windows-Optimization-Guide for Chromium Edge, AveYo OpenWebSearch for protocol redirect):
1. Detect legacy Edge (CBS package `Microsoft-Windows-Internet-Browser-Package~~` under HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Component Based Servicing\Packages) and Chromium Edge (folders Edge/EdgeCore/EdgeUpdate under Program Files / Program Files (x86)\Microsoft, or Win32_InstalledStoreProgram Microsoft.MicrosoftEdge.Stable).
2. Before removal copy ie_to_edge_stub.exe (from %ProgramData%, %Public%, or Program Files (x86)\Microsoft\Edge) into C:\ProgramData\Winhance\OpenWebSearch\ to use as redirect stub later.
3. Stop processes: MicrosoftEdgeUpdate, OneDrive, WidgetService, Widgets, msedge, Resume, CrossDeviceResume, msedgewebview2.
4. Legacy: set the CBS package Visibility=1, delete its Owners key, `dism /online /Remove-Package` with a 30 s timeout and one retry, plus Remove-AppxPackage Microsoft.MicrosoftEdge.
5. Chromium: create a fake C:\Windows\SystemApps\Microsoft.MicrosoftEdge_8wekyb3d8bbwe\MicrosoftEdge.exe (the trick that lets Edge's own uninstaller run), find "Microsoft Edge" uninstall strings under HKLM\SOFTWARE\WOW6432Node\...\Uninstall, run `<uninstallString> --force-uninstall --silent` (or `/quiet` for msiexec MSI variant), Remove-AppxPackage Microsoft.MicrosoftEdge.Stable, delete the fake folder. Then EdgeUpdate: back up HKLM\SOFTWARE\WOW6432Node\Microsoft\EdgeUpdate\ClientState (explicitly "or else WebView won't work"), `MicrosoftEdgeUpdate.exe /unregsvc`, wait for setup/MicrosoftEdge* processes, `/uninstall`, then re-import ClientState. WebView2 is deliberately preserved (folders matching *EdgeWebView* are excluded from deletion).
6. Cleanup: delete Program Files (x86)\Microsoft\*Edge*/*Temp* dirs, shortcuts (desktop, quick launch, taskbar pinned + tombstones, start menu for all profiles incl. Default/Public), registry keys (HKLM/HKCU SOFTWARE\Microsoft\Edge, EdgeUpdate, Clients\StartMenuInternet\Microsoft Edge, App Paths\msedge.exe, Uninstall\Microsoft Edge, Eventlog entries for Edge/edgeupdate/edgeupdatem, RegisteredApplications "Microsoft Edge", Classes MicrosoftEdgeUpdate*/MSEdge*, MuiCache entries), C:\ProgramData\Microsoft\EdgeUpdate, C:\Windows\Temp\MsEdgeCrashpad, per-user AppData\Local\Microsoft\Edge.
7. Redirect: HKCR\MSEdgeHTM\shell\open\command -> stub; HKCR\microsoft-edge protocol -> stub via IFEO Debugger running OpenWebSearch.cmd (opens the real default browser, falls back to scanning HKCU/HKLM SOFTWARE\Clients\StartMenuInternet); deletes any stale IFEO\msedge.exe key ("to prevent Edge reinstall issues"); removes every scheduled task whose name matches *Edge* (except EdgeRemoval).
Caveats in comments/descriptions: Edge and App Installer are flagged HasInstabilityWarning in the app list (removal can break WebView2/Store-adjacent features and winget); Edge appx entry is CanBeReinstalled=true via WinGet Microsoft.Edge / Store XPFFTQ037JWMHS; Windows Update/EdgeUpdate may reinstall Edge, hence the AtStartup EdgeRemoval task.

OneDrive (OneDriveRemoval.ps1): detect target user (Win32_ComputerSystem.UserName, fallback explorer.exe owner) when running as SYSTEM; Remove-AppxPackage OneDrive; run the OneDriveSetup uninstall string from HKLM then HKU\<SID> `...\Uninstall\OneDriveSetup.exe` (stops OneDrive processes first); always-cleanup: delete those Uninstall keys and OneDrive config keys (HKLM\SOFTWARE\Microsoft\OneDrive, HKLM\SOFTWARE\WOW6432Node\Microsoft\OneDrive, plus per-user keys), user AppData\Local\Microsoft\OneDrive (takeown/icacls), Start Menu shortcuts (user + C:\ProgramData\Microsoft\Windows\Start Menu\Programs\OneDrive.lnk), C:\Windows\System32\OneDriveSetup.exe and SysWOW64 copy (schedule delete on reboot via MoveFileEx flag 4 if locked), scheduled tasks matching *OneDrive* (except OneDriveRemoval), and a one-time (marker HKLM\SOFTWARE\Winhance\OneDriveRemoval\DefaultUserConfigured) edit of the Default user hive: delete Run\OneDriveSetup and set SOFTWARE\Microsoft\OneDrive\EnableTHDFFeatures=0 so new profiles don't get OneDrive. User data under %USERPROFILE%\OneDrive is preserved. Related policy entry: privacy-onedrive-auto-backup (known-folder backup prompts).

Defender: Winhance does NOT remove or disable Microsoft Defender. Only Defender-adjacent items exist: Windows Security notifications (notifications-windows-security, security-maintenance), Smart App Control state (HKLM\SYSTEM\CurrentControlSet\Control\CI\Policy\VerifiedAndReputablePolicyState), VBS / Memory Integrity toggles, and a warning on the Take Ownership context-menu item that Defender may need to be temporarily disabled. No tamper-protection or service/Sense removal logic was found in the repo.

Version caveats: Win11 24H2+ items gated by build (see Notes above); WordPad is already removed by default in 24H2; Mixed Reality Portal deprecated in 24H2; Windows Maps, People, Skype, Paint 3D, Tips, Cortana, Xbox Game Bar plugin are unpublished/deprecated in the Store (CanBeReinstalled=false => removal is effectively permanent). Legacy "Notepad (Legacy)" and "Paint (Legacy)" are capability packages distinct from the Store Notepad/Paint appx. AI Workload/Copilot+ appx families (WindowsWorkload.*, MicrosoftWindows.Client.AIX/CoPilot) are marked not reinstallable.
